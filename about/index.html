Serhii Kravchenko — MCP engineer

Yes MCP is my practice, not a company with a floor of engineers. One person does the work; that is the honest shape of it, and it is why everything published here can be traced to something I ran myself.

What I have actually built

A Model Context Protocol server that runs in production and is used daily — not a demo repository. It is a remote connector: OAuth 2.1 resource server with the RFC 9728 discovery document, tokens issued by a real identity provider, per-user state, an audit trail, session limits and an idle timeout. It serves a live user through Claude on the web, on a phone and on the desktop.

On top of it, interactive interfaces — MCP Apps views — that render inside the assistant with real data: a card the user ticks, a source card with verbatim quotes. Those are shipped and verified on Claude's web and mobile clients, which is a narrower claim than it sounds: most of what exists in this space has been seen working in one client, on a developer's machine.

And the measurements. The findings in the writing came out of that server: which channels between a server and a model actually arrive, what the protocol overhead really costs per call, how a host behaves differently in one mode than another. Each was caught by a cheap decisive test rather than by reading the documentation, because the documentation was repeatedly wrong.

What I am not

I am not a twenty-year systems engineer, and pretending otherwise would be found out in the first technical conversation. I came to this from the outside: two years ago I left e-commerce with no technical background and went all in on AI, building real things until they held. What that path produced is a habit of trusting nothing that has not been tested on a live system — which happens to be the exact skill this technology rewards, because the specifications and the hosts disagree constantly.

I also have no client case studies to show yet, and there are none invented on this site. When there are, they will appear with the client's permission and with numbers that can be checked.

How these notes are produced

The findings are mine — measured on systems I run, with the commands and outputs kept. The prose is written with AI assistance, which is worth stating plainly on a site about AI tooling. Every number published here was produced by a command whose output I read; nothing is estimated and presented as measured. Where a claim is a hypothesis rather than a result, it says so.

If something here turns out to be wrong, I would rather hear it and correct it in place with a dated note than quietly edit the page. Corrections go to the address below.
