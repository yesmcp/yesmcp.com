MCP engineering for companies that don't want to hire for it

The Model Context Protocol is how an AI assistant reaches into your systems: your ERP, your CRM, the in-house tool nobody outside the company has ever heard of. I build those connections, make them safe enough for real data, and keep them working as the protocol keeps moving.

Most of what gets written about MCP is written from the specification. Everything on this site comes from a server that actually runs in production, with OAuth, a real user, and logs I read every day. Where a claim below was measured, the measurement is shown next to it.

MCP is the newest layer of longer work: putting AI agents inside organisations where people actually work, across HR, sales, marketing, lead generation and IT, and training the teams who then have to live with them. More about that.

What we do

Four kinds of work

Servers for internal and legacy systems

The systems no vendor will ever ship an official MCP server for: in-house tools, regional software, the database behind a twenty-year-old process. The protocol is rarely the hard part. The hard part is choosing which handful of actions a model gets, and which ones it must never take on its own.

Security and authorisation review

Published surveys of public MCP servers keep finding the same two holes: no authorisation at all, or one static API key standing in for it. I review what you have against how hosts actually behave, and fix the parts that only look safe.

Readiness for the 2026-07-28 specification

The July release turned the protocol stateless and deprecated the old transport, with twelve months to move. If your server holds per-session state, it is on that clock. I audit what really depends on sessions and write the migration plan. The note below explains why the migration itself cannot be carried out yet.

Interactive UI inside the chat (MCP Apps)

Not every answer should be a paragraph. A queue with approve buttons, a card, a tracker the user ticks off, all rendered inside the assistant and backed by your data. I have shipped these to Claude on web and on mobile, and can tell you exactly where the edges are.

Notes from production

Writing

Each of these started as something that broke, surprised me, or contradicted the documentation. The numbers are mine and can be reproduced.

  • 2026-08-10 The MCP spec shipped one day after its SDK, and it still can't speak it

    The stateless rewrite landed on 28 July with a twelve-month migration window. The TypeScript SDK that would implement it was published on 27 July, and it tops out at the November 2025 protocol. Nobody is migrating yet. Worth knowing before you plan a sprint.

  • 2026-08-10 Your tool results are being read as an attack

    I put behaviour rules in the text my tools returned, because the proper channel never reached the model. Then a user watched the host warn them that this connector had tried to inject malicious instructions. About the shape of it, the detector was right.

  • 2026-08-10 What the host doesn't deliver

    A field guide to the channels between your server and the model: which ones arrive, which quietly do not, and what each one costs. Four findings, none of them from reading the specification.
